# 小程序会员余额查询

客户在小程序登录并单独授权手机号后，通过手机号关联后台客户档案，在「我的预约」直接查看已迁入账户的余额合计。点「查看余额与明细」进入各门店账户及流水。服务号绑定、发送“余额”均为可选操作，不是小程序查询的前置条件。

## 查询与更新

- 「我的预约」和「个人资料」的余额摘要、余额详情页，进入时立即请求 `/api/me/wallets`。
- 页面可见时，每次查询完成后 15 秒再次读取；点「刷新余额」立即重查，重复点击合并为同一次请求。
- 页面隐藏、离开或小程序退到后台时停止定时查询；回来时立即刷新。H5 隐藏浏览器标签页同样停止余额轮询。
- 同一账号页面恢复、后台录入期初余额、充值、消费或冲正后，下次查询读取后台当前数据。不把余额写入客户端持久缓存。
- 页面展示查询时间；断网或接口失败时，已加载金额标记为“上次查询结果”，初次失败不显示虚构的零余额。退出登录或切换客户会丢弃先前查询结果。
- 后端余额 API 带 `Cache-Control: no-store`；服务号绑定接口仅在展开「服务号查询（可选）」后读取，其异常不影响小程序余额。

这里的“自动更新”是可见页面约 15 秒的定时查询，加上请求耗时；后台变更后并非毫秒级主动推送。

## 分批迁移

| 后台情况 | 小程序显示 |
| --- | --- |
| 已授权手机号，但尚未核实会员身份、没有余额账户 | 会员资料待核实 |
| 已核实会员身份，尚未录入期初余额账户 | 余额待迁移核对 |
| 已录入一个或多个账户 | 展示各门店余额，以及已迁入账户合计 |
| 真实账户余额为零 | 显示 ¥0.00 |

酷鼠仍未迁入的账户不计入合计，也不当作零余额。后台应按同一已核实手机号关联档案、录入期初余额；后续迁入的账户无需客户重新登录或绑定服务号。此功能不自动同步酷鼠接口。

## 更新和测试

1. 服务器先使用支持 `/api/me/wallets` 的会员余额 Java 版本。自动刷新复用现有余额 API，这一轮没有新增数据库迁移。
2. 本机项目为 `D:\github_code\裕和堂相关项目\yuhetang-miniprogram`，微信开发者工具打开项目根目录，小程序目录为 `dist/weapp/`。需要重新构建时执行 `npm run build:weapp`。
3. 点击编译并重新预览；手机体验版需重新上传、设为体验版后扫码进入。本轮入口和刷新逻辑属于客户端代码，旧手机版本不会因服务器更新自动替换。
4. 客户微信登录、授权手机号，进入「我的预约」。未绑定服务号也应能看到后台已录入余额。
5. 在管理后台该客户的「会员余额」录入一笔真实、经确认的充值或消费。页面停留时等待约 15 秒，或点「刷新余额」，核对金额和流水。正式会员账户请使用经核实的业务数据。
6. 对仍未迁入的会员，先核对待迁移提示，再由后台录入期初账户；客户端停留期间应自动出现新账户。

本地验证：`npm run check:mini`；微信构建完整性及原生 WXSS 检查随 `npm run build:weapp` 执行。`npm run build:h5` 后执行 `node tools/verify-wallet.mjs`，用隔离接口验证自动刷新、隐藏/恢复、服务号故障隔离、迁移中状态及中英日文布局。该浏览器检查不访问生产接口，也不修改真实会员余额。
